# 正社員のチャットのヒアリングも、何を聞くかを dip のハーネスが決める

ADR-0009 では、アルバイト・パートのチャットの相談に限って、何を聞くか、いつフェーズを切り替えるか、いつ終えるかを dip のコード
(ハーネス)が決めることにした。正社員のチャットは playbook(`fulltime_chat.md`)のまま残した。その正社員のヒアリングは、
利用者から「大雑把でよくない」と評価された。何を聞くか、いつ終えるかをモデルに任せているので、職務経歴書の材料(成果、数字)を
集めず、構造化された出力が無いので測れない(設計メモ [fulltime-hearing.md](../design/fulltime-hearing.md) §2)。

設計メモに沿って、**正社員のチャットのヒアリングも、何を聞くか、いつフェーズを切り替えるか、いつ終えるかを dip のハーネス
(`dip_mcp/career/`)が決める**ことにした(task 245)。ADR-0009 を正社員に広げる。形は v4.1 と同じ 3 段の `turn()`(抽出 →
ハーネスの判断 → 生成)で、モデルは抽出の JSON と `{"reply"}` だけを返す。正社員だけのものは次の 3 つ。

- **職歴カード。** 直近の職歴 2 件を 1 枚ずつ、3 つの欄(何をしていたか / どのくらい / どうなったか)で埋める。role と result の
  問いには答えの候補のボタンを出さず、「覚えていない」「パス」だけを出す(誘導しないため)
- **時間の予算。** 本人の推定時間(読む 400 字/分、打つ 40 字/分、ボタン 1 回 2 秒)を、ターンの数と並べて予算にする。
  質問を止める時刻(目標時間 - 90 秒。履歴書なし 210 秒、あり 90 秒)を過ぎたら、空いている HARD のほかは聞かずに review に進む。
  `MAX_TURNS = 16`。本人は短気で時間がないと決めて測る(設計メモ §6.1)ので、ターンだけでは止まる前に離脱する
- **出題の優先度。** HARD > 1 枚目の職歴カード > 2 枚目 > MID と LOW を、出題のスコアで決める。segment が後から決まったときの
  HARD も、hard_filter より後のどのフェーズでもスコアで比べ、2 枚目のカードや場面の二択より先に聞く

ほかは v4.1 にそろえる: 質問バンクはデータ(`dip_mcp/career/bank.json`)、確信度と from はハーネスが決める、まとめのカードで
推し量った値を一度に確かめる、ボタンはモデルを呼ばない、モデルの出力が壊れても 1 回やり直し、だめなら質問の原文で返す。
加えて、本人の言葉のまま入れる(今の問いへの文は、本人の文をそのまま入れる)、数は発言に数字で書いてあるときだけ入れる、
自由に打った文を正規表現で読まない(読めなければボタンで 1 回だけ聞き直す)、を決めた。

ゲームの仕組み(場面の二択、逆選択、進み具合と 1 行)を入れるかは、設定 1 つで切り替える(形 B と C。設計メモ §6.5)。
既定は C。どちらが情報を多く取れるかは、実 API の比べ(5/5 のタスク)で決める。

## Considered Options

- playbook を絞って、正社員の相談をモデルに任せたままにする: 職歴カードの欄の聞き漏れと、時間の使いすぎを確かめられない。
  モックの回帰も回せない
- アルバイト・パートのハーネス(`dip_mcp/baito/harness.py`)に正社員の区分を足す: v4.1 は PRD の参照実装と単体チェック 131 件に
  合わせた移植で、職歴カードと時間の予算を足すと PRD の検査で回せなくなる。正社員は別のパッケージにし、形と名前だけをそろえる
- ターンの数だけで止める(v4.1 と同じ): 正社員は文で答える問いが多く、1 ターンの時間がばらつく。モックでも、文で答える人は
  12 ターンほどで 4 分を超える(設計メモ §7)
- まとめと結果の文もモデルに書かせる: カードの字数(200 字)と時間を守れなくなる。まとめと結果はハーネスの決まった文にした

## Consequences

- ADR-0001 の「次の質問をコードで決めない」は、正社員のチャットのヒアリングにも当てはまらなくなる。トークへのつなぎは 2b のタスク
  (task 255)で作った: dip のツール(`start_career_consultation` / `career_turn` / `end_career_consultation`)、LINE のランタイム
  (`_harness_turn`)、保存(条件を `stated_preferences` に、職歴カードをプロフィールの `career_profile` に)。本番の切り替えは
  機能フラグ `CAREER_HARNESS_VERSION=c1` で分け、無ければ(既定)正社員のチャットは playbook のまま
- 正社員の相談には、区分に共通の「相談の問いは 4 問まで」(`consult_length_violations`)は当てはまらない。上限は時間と
  `MAX_TURNS` で決める。チェッカーは、ハーネスのターン(返信に `career` が付く)を数えない(task 255)
- 回帰は `python -m evals.career_sim`(1/5 の事実表のペルソナ 6 人 × 形 B と C。モックの本人役とモックの読み取り。費用 0)と
  `tests/test_career_harness.py`。モックの読み取りは正解を返すので、確かめられるのはハーネスの動きだけ。正しく取れた事実、
  誘導、面接口調は、実 API の比べ(5/5 のタスク)で見る
- 音声の正社員の面談は、playbook のまま
