# 全部の入り口に共通の会話の層: 発言を働きで読み、ハーネスが応じ方を決め、LLM が 1 つの返事に組む

ADR-0009 と ADR-0010 で、アルバイト・パートと正社員のチャットの相談は、何を聞くかをハーネス(`dip_mcp/baito/`、`dip_mcp/career/`)が
決める形にした。聞き漏れは減ったが、本番の LINE で運営者が正社員ヒアリングを試し、「アホすぎ」と言った(2026-10-28、jyoka/tasks#326 のトーク)。
「他の候補です。」とだけ返す、年収を上げたいと言った人に「今より上げたい」を出す、区切りの文が相づちより先に来る、などが出た。
運営者は、どの入り口から始まっても同じ要求になると追記した。調べると、根は 4 つだった(設計メモ [conversation-layer.md](../design/conversation-layer.md) §2.6)。

- 読む段が、1 つの発言を決まった数の intent の 1 つにしか分けない(正社員 8 種、アルバイト・パート 6 種)。直す、怒る、言い足す、別の入り口の話は落ちる
- 言う段は、固定の文と問いの原文の貼り合わせで、LLM が書けるのは短い相づちだけ。並べる順もコードが固定している
- 決める段は、何が空いているかだけで問いと候補を選び、分かっていることの中身を見ない
- 入り口の間に会話の層が無い。発言の種類、検証、やめる合図、危ない言葉の確かめを入り口ごとに別々に作り、入り口をまたぐ話は正規表現とトークの AI に任せている

場面ごとに、入り口ごとに直すと、この箱を足し続けることになる。そこで、**会話の層を全部の入り口に共通の部品(`dip_mcp/convo/`)にし、
1 ターンの 3 段(読む → 決める → 言う)はそのままに、段ごとの受け持ちを広げる**ことにした(task 327)。

- **層と入り口を分ける。** 読む、値の当て方、入り口の移り方、応じ方の計画、問いの選び方、言う、守りの前処理は層が受け持つ。
  入り口ごとの違い(欄、質問バンク、事実、言い回しの調子、決まった文、上限、画面、移る先)は入り口の定義(データ)にする。
  未成年の決まりのような入り口だけの決まりは、小さなコードとして入り口に残す。新しい入り口は、入り口の定義を足すだけで同じ振る舞いになる
- **読む: 発言を、複数の「働き」(act)で読む。** 答え、ほかの欄の答え、直す、取り消す、迷う、雑談、逆質問、感情、危ない話、別の入り口の話などを、
  1 つの発言から同時に取る。値の抜き出しは今と同じく発言の部分文字列で、数は数字で書いてあるときだけ。読む段にも直前のやりとりを渡す
- **決める: ハーネスが「応じ方の計画」を作る。** 何に応じるか、渡す事実(データ `facts.json`)、注意の 1 行、区切りの 1 行、次の問いを、
  決まった順の部品(相づち → 答え → 注意 → 区切り → 問い)にする。問いは固い順でなく、優先度と今の話題で選ぶ。前の答えから推せる欄は
  聞かずにまとめで確かめる。値の確かさ、予算、まとめ、結果は今のまま
- **入り口を途中で変えられる。** 移りたい発言(「やっぱり正社員で」「とりあえずバイトでいい」)は、同じターンで次の入り口へ移る。
  考えているだけの発言(「正社員も考えてる」)は移らずに、移るボタンを出す。値は希望の項目(`stated_preferences`)と、1 回だけ使う引き継ぎの記録で渡し、
  移った先で聞き直さない。年収と時給のような換算はしない
- **言う: LLM が計画から 1 つの返事を書く。** 書くのは相づち、つなぎ、逆質問の答えの言い方だけ。問いの文は質問バンクの言い方(2〜3 通り)から
  一字一句選ぶ。調子は入り口の定義から渡す。ハーネスが、部品の順、言い回しの重複、事実と数、字数を確かめ、だめなら決まった組み立てで返す
- **守りは今の決まりを残す。** 事実を作らない(ADR-0003)、回数と時間の上限、1 ターンの LLM の呼び出し 2 回(上限 4)、未成年と闇バイトの決まり。
  危ない言葉の確かめを、アルバイト・パートの中から層の前処理に移し、全部の入り口で LLM の前に見る
- **入り口ごとに扱いを分ける。** 正社員(`CAREER_HARNESS_VERSION=c2`)とアルバイト・パート(`BAITO_HARNESS_VERSION=v5`)は層に載せ替える。
  トークの AI はエージェントのまま、前処理と事実と入り口を選ぶ問いだけを足す(`TALK_LAYER_VERSION=t1`)。決まった返信の入り口
  (履歴書の確認、ゲームの後、音声相談の後、同意)は層に入れない。音声相談(`voice_resume/`)の会話も層に入れず、事実、危ない言葉、共通の値だけを共通にする
- **移る順は、正社員 → アルバイト・パート → トークの AI。** 入り口ごとに環境変数で切り替える。今の版は残し、始めた相談は始めた版のまま最後まで進める

設計メモ §6 の点は運営者が決めた(2026-10-29)。設計メモ §5 の 10 枚のカードで作っている(2026-10-29 は 3 枚目まで。共通の部品は `dip_mcp/convo/`、正社員は `CAREER_HARNESS_VERSION=c2` で試せる。本番は今の版のまま。進み具合は設計メモ §7)。

## Considered Options

- **今の作りのまま、場面ごと、入り口ごとに直す。** #326 はこの形で直す。ただし、雑談、直す、怒る、言い足す、別の入り口の話のような発言の種類は無数にあり、
  箱と固定の文を入り口の数だけ足し続けることになる。運営者が「場面ごとに直していては、毎回このような修正が要る」と言ったとおり
- **会話は LLM(エージェント)に任せ、ハーネスは値の検証だけにする。** ADR-0010 の前の形(playbook)に近い。自然にはなるが、
  何を聞くか、いつ終えるかが毎回ばらつき、実 API で事実が 2.5 項目しか取れなかった(fulltime-hearing.md §7 の形 A)。採らない
- **全部の入り口をトークの AI 1 つにまとめる。** 入り口をまたぐ話は自然に受けられるが、上と同じく何を聞くかがばらつく。
  未成年の決まりのような守りもプロンプト頼みになる。採らない。トークの AI は、何をするかが開いた相談の外の受け皿として残す
- **読むと言うを 1 回の LLM の呼び出しにまとめる。** 速く安いが、読んだ値でハーネスが次の問いを決める前に返事を書くことになり、
  何を聞くかをハーネスが決める形が崩れる。採らない
- **問いの文も LLM に自由に言い換えさせる。** 単調さは消えるが、task 315 で直したあいまいな問い(「規模は?」)に戻りうる。
  言い換えたかをコードで確かめられない。質問バンクに言い方を 2〜3 通り置く形にした
- **アルバイト・パートの v4 を書き換えて層に載せる。** v4 は PRD の参照実装の移植で、PRD の単体チェック、付録 C の名前、プロンプトの原文で縛っている
  (ADR-0009)。書き換えると戻せない。v4 を残し、v5 を別の版として作る
- **音声相談も同じ層に入れる。** 入り口が 1 つの作りになるが、音声はリアルタイムで、読む → 決める → 言うの 2 回の呼び出しは話し出すまでの待ちを増やす(推測)。
  ボタンもカードも無い。今は事実、危ない言葉、共通の値だけを共通にし、待ち時間を測ってから別に決める

## Consequences

- 場面の一覧(`evals/scenes/`。入り口ごとと、入り口をまたぐもの。テストで 60 場面以上を確かめる)を、会話の層の物差しにする。
  条件はコードで判定するものと、LLM の採点の 2 種類(一覧は `evals/scenes/__init__.py`)。1 枚目のカードで回す仕組みを作り、今の作りの点を出してから作り始める
- どの入り口も、1 ターンの LLM の呼び出しの数は変わらない。入り口を移すターンはトークの AI を挟まないので減る。入力は 4〜6 割増えると見込む(推測)。
  待ち時間と費用は 9 枚目のカードで入り口ごとに測る
- 入り口の間で別々に作っていた部品(発言の種類、検証、`_call_llm`、`match_button`、やめる合図、危ない言葉)は `dip_mcp/convo/` にまとまる。
  v4 と c1 は残すので、移行の間は 2 つの作りが並ぶ
- dip の状態に、1 回だけ使う引き継ぎの記録が増える。データを消すとき、新しい会話のときに一緒に消す
- アルバイト・パートの v5 では、PRD の検査のうち `turn()` の形とプロンプトの原文を見るものを v4 だけに残す(運営者が決める)。ADR-0009 の縛りは v4 に残る
- 運営者が決めること(面白さの方向、LLM に任せる範囲、費用の上限、入り口を移す順、v5 と PRD の検査、トークの AI と音声相談の扱いなど 21 点)は、設計メモ §6 にある
- ADR-0009 と ADR-0010 の「何を聞くか、いつ終えるかはハーネス、モデルは抽出と言い方」は変わらない。言い方の受け持ちが、短い相づちから、
  計画に沿った 1 つの返事に広がる
