# アルバイト・パートのチャットの相談は、何を聞くかを dip のハーネスが決める

ADR-0001 では「次に何を聞くか」をコードで決めないことにした(v1 の相談が項目を順に埋めるだけで浅かったため)。その後、
アルバイト・パートの相談について「範囲が広すぎる」と評価された: 何を聞くか・いつ終えるかをモデルに任せたので、質問の順・数・深さが
毎回ばらつき、必須の項目(年齢・学校の許可・副業の可否)の聞き漏れと、際限のない深掘りが起きる。条件に優先度が無く、高校生・主婦・
副業の会社員を振り分けず、未成年の深夜労働のような決まりもモデルの記憶に頼っていた。

PRD「バイト探しの相棒」v4.1([PRD](../prd/baito_harness/PRD_baito_agent_v4.md)。v3 を置き換えた)に沿って、**アルバイト・パートの
チャットの相談に限り、何を聞くか・いつフェーズを切り替えるか・いつ終えるかを dip のコード(ハーネス、`dip_mcp/baito/`)が決める**
ことにした(task 242)。モデル(LLM)は抽出と言い方だけを受け持つ。浅くならないよう、深さはシナリオの二択(好みの推し量り)と、
条件のまとめのカードで推測をまとめて確かめることで作る。

- 1 ターンは 3 段の `turn()`: 抽出(選択肢そのものならモデルを呼ばずに choice_effects を当てる。文ならモデルに JSON で読み取らせる)
  → ハーネスの判断(確信度と from はハーネスが決める。未成年・中学生・闇バイトの決まり、次の質問とフェーズ)→ 生成(モデルは
  `{"reply"}` だけを返し、ハーネスが質問の原文が入っているか・金額が無いかを確かめる)。モデルの出力が壊れても 1 回やり直し、
  だめなら質問の原文で返す
- ハーネスは参照実装 `harness_v4.py` を移したもの(`dip_mcp/baito/harness.py`。PRD 付録C の名前をすべて持つ)。質問バンク 49 問と
  職種カタログ 24 件は JSON のデータ(`bank_v4.json`・`catalog_v4.json`)にだけ置き、プロンプトに書かない。プロンプト 4 種は
  `dip_mcp/prompts/baito/` に PRD の原文のまま置く
- 未成年(年齢が分からない・答えないを含む)は、どの区分でも NG「深夜シフト」「重量物・危険な作業」が付き、深夜の選択肢を出さず、
  深夜専用・18歳以上・重労働の仕事を推薦しない。中学生以下は推薦に進まない(年齢の質問に文で答えて抽出が失敗しても止める)。
  止めた後に相談を閉じても印(dip の `baito_block`)を残し、トークの AI が探しても `recommend_jobs`・`relax_conditions` は
  求人を返さない(後の相談で 15 歳以上と確かめたら消す)。どれもコードで強制する
- dip は LLM を呼ばない(HLD 1.1)。`turn()` がモデルを呼ぶところで、dip のツール `baito_turn` は `status=llm` とプロンプトを返し、
  LINE 側のランタイムがモデルを呼んで、それまでの出力を全部渡して呼び直す。`turn()` は同じ状態と同じ出力からは同じ道をたどるので、
  dip は最後まで進んだ回だけ状態を保存する(1 ターンにモデルは最大 4 回、ツールは最大 5 回)
- 入口と体験の骨格は今のまま: トークの AI が相談に入ると決め(dip の Prompt の「相談」)、`get_counseling_playbook` でアルバイト・
  パートの playbook を読む。機能フラグ `BAITO_HARNESS_VERSION=v4` のときだけ、その playbook がハーネス版
  (`parttime_chat_harness.md`)になり、同じターンに `start_baito_consultation` を呼ぶ。その後の本人の発言はランタイムがハーネスに
  渡す。結果に着くと条件を `stated_preferences` に保存し、トークの AI に戻る(中学生以下で止めたときだけは戻らない)

## Considered Options

- 今の作り(playbook に指針だけを書き、何を聞くかはモデルが決める)のまま、playbook を絞る: 上の問題(聞き漏れ・ばらつき・コンプライアンス)は
  プロンプトでは確かめられず、20 ペルソナの回帰も回せない
- 相談を別のエージェント(グラフのノード)にする: ADR-0001 と同じ理由で採らない。会話は同じスレッドのまま、ターンの受け持ちだけを替える
- ハーネスを LINE 側(`line_runtime/`)に置き、そこでモデルを呼ぶ: 何を聞くか・コンプライアンスは業務の規則なので、HLD の 1.1 のとおり
  dip 側の関数にする。dip にモデルを呼ばせないため、出力を受け取りながらやり直す形にした
- `turn()` を段ごとの関数に割り、途中の状態を保存する: 参照実装と単体チェック(付録C)の形が変わり、移植版を PRD の検査で回せなくなる

## Consequences

- ADR-0001 の「次の質問をコードで決めない」は、フラグを入れたときのアルバイト・パートのチャットの相談には当てはまらない。正社員・
  未定のチャットと、音声の面談(`parttime_voice.md` も含む)は playbook のまま
- 本番はまだ切り替えない(フラグの既定は無し)。切り替えは PRD §16-1 の法務の確認(注意文 15 種)と §12-2 の確認の後(PRD §13-1 P4)。
  始めた相談は、フラグを戻しても最後まで v4 で進める。`version` の無い保存状態(v3)は本番に出していないので、閉じて始め直す
- アルバイト・パートの相談は最大 15 ターン(PRD の `MAX_TURNS`)で、区分に共通の「相談の問いは 4 問まで」は当てはまらない。
  実 API の評価(`evals/run.py`)のアルバイト・パートの相談のシナリオは、フラグを入れて測り直しが要る(ハーネスのターンの返信には `baito` が付く)
- 回帰は `evals/baito_sim.py`(PRD の単体チェック 131 件と 20 ペルソナを、移植版で回す。費用 0)と `tests/test_baito_harness.py`。
  実モデルでの測定(PRD §13-1 P3)は `evals/baito_sim.py --real` で回すが、まだ回していない(予算の承認が要る)
- PRD §12-2(review を 2 巡しても解けない矛盾): ユーザーの決定どおり、値を消して「未定」にし、記録した候補を結果の文に並べる。
  推薦の絞り込みでは空として扱う
- 抽出の JSON の `ng_removals` で本人の NG を外せる(ユーザーの決定)。ルールの NG(未成年)は外せず、年齢を 18 歳以上に直すと外れる
