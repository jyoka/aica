# アルバイト・パートのチャットの相談は、何を聞くかを dip のハーネスが決める

ADR-0001 では「次に何を聞くか」をコードで決めないことにした(v1 の相談が項目を順に埋めるだけで浅かったため)。その後、
アルバイト・パートの相談について「範囲が広すぎる」と評価された: 何を聞くか・いつ終えるかをモデルに任せたので、質問の順・数・深さが
毎回ばらつき、必須の項目(年齢・学校の許可・副業の可否)の聞き漏れと、際限のない深掘りが起きる。条件に優先度が無く、高校生・主婦・
副業の会社員を振り分けず、未成年の深夜労働のような決まりもモデルの記憶に頼っていた。

2026-10-26 の PRD「バイト探しの相棒 v3」([PRD](../prd/baito_harness/PRD_baito_agent.md))に沿って、**アルバイト・パートの
チャットの相談に限り、何を聞くか・いつフェーズを切り替えるか・いつ終えるかを dip のコード(ハーネス、`dip_mcp/baito/`)が決める**
ことにした(task 242)。プロンプトは「どう言うか」だけを受け持つ。浅くならないよう、深さはシナリオの二択(好みの推し量り)と、
条件のまとめのカードで推測をまとめて確かめることで作る(PRD §2・§5)。

- 質問は質問バンク(`dip_mcp/baito/bank.json`、48 問)のデータにだけ置き、プロンプトに書かない。質問文と選択肢は PRD の原文のまま
- モデルは毎ターン決まった JSON(reply / choices / slot_updates / ng_updates / segment)だけを返す(構造化出力)。
  ハーネスがそれを 3 層の条件表(ゆずれない条件・こだわり・NG)にマージし、次の質問を決める
- 未成年の NG「深夜シフト」と、segment が分からなくても年齢を聞くことは、コードで強制する。未成年の深夜の時間帯は、
  列挙値でも本人の文(深夜の語・深夜の時刻)でも受け付けない。18歳未満かが はい / いいえ に寄らない答えは残さず、年齢を聞き直す。
  「未成年ではありません」のような打ち消しは 18歳未満と読まない。ただし別のことを打ち消した文(「いいえ、ちがいます。高2です」)は、
  残る学年や年齢で 18歳未満と読む。18 ちょうどは年齢だけの答え(「18歳です」)のときだけ成人と読み、
  「まだ18歳になっていません」「もうすぐ18歳」のような言い方は聞き直す
- 入口と体験の骨格は今のまま: トークの AI が相談に入ると決め(dip の Prompt の「相談」)、`get_counseling_playbook` の代わりに
  dip のツール `start_baito_consultation` を呼ぶ。その後の本人の発言は、LINE 側のランタイムがハーネス(dip のツール `baito_turn`。
  トークの AI には見せない)に渡し、ハーネスのシステムプロンプトでモデルを呼ぶ。結果に着くと条件を `stated_preferences` に保存し、
  トークの AI に戻る。ハーネスのターンも同じ会話に保存するので、画面の描き直しと、その後のトークの AI の文脈はそのまま
- 本人が選択肢を押したときは、モデルに読み取らせず choice_effects をそのまま当てる。文で答えたときだけ、先にモデルに読み取らせる
  (1 ターンにモデルを 2 回呼ぶ)。読み取りの前に次の質問を決めると、segment やフェーズの切り替えが 1 ターン遅れるため

## Considered Options

- 今の作り(playbook に指針だけを書き、何を聞くかはモデルが決める)のまま、playbook を絞る: 上の問題(聞き漏れ・ばらつき・コンプライアンス)は
  プロンプトでは確かめられず、8 ペルソナの回帰も回せない
- 相談を別のエージェント(グラフのノード)にする: ADR-0001 と同じ理由で採らない。会話は同じスレッドのまま、ターンの受け持ちだけを替える
- ハーネスを LINE 側(`line_runtime/`)に置く: 何を聞くか・コンプライアンスは業務の規則なので、HLD の 1.1 のとおり dip 側の関数にする
- 1 ターンにモデルを 1 回だけ呼び、次の質問は本人の答えを読む前の状態で決める: 文で答えたときに segment の判明とフェーズの切り替えが
  1 ターン遅れ、PRD のシミュレーション(読んでから決める)と食い違う

## Consequences

- ADR-0001 の「次の質問をコードで決めない」は、アルバイト・パートのチャットの相談には当てはまらない。正社員・未定のチャットと、
  音声の面談(`parttime_voice.md` も含む)は playbook のまま
- アルバイト・パートの相談は最大 15 ターン(PRD の `MAX_TURNS`)で、区分に共通の「相談の問いは 4 問まで」は当てはまらない。
  実 API の評価(`evals/run.py`)のアルバイト・パートの相談のシナリオは、測り直しが要る(ハーネスのターンの返信には `baito` が付く)
- 回帰は `evals/baito_sim.py`(モックの LLM で 8 ペルソナ。費用 0)と `tests/test_baito_harness.py` で見る。実モデルでの言い方
  (1 ターン 1 問・リアクション・途中の気づき・面接口調なし)は、PRD §11.3 の 9 のとおり実 API で抜き取って確かめる
- PRD §12 の 2(review を 2 回しても残る矛盾を、最後の推測値のまま残すか空欄にするか)はユーザーが決めていない。今は最後の推測値が残る
- モデルの JSON には、PRD §12 の 3(NG の取り消し)のために任意のキー `ng_removals` を足した。PRD の 5 つのキーは変えていない
