# 雇用区分と playbook だけを dip のツールにし、会話の段階はツールにしない

アルバイト・パートに加えて正社員を扱うにあたり、「いまどちらを探しているか(雇用区分)」を dip のツール `set_search_track`(根拠の発言つきで記録)で切り替え、相談の進め方(playbook)を `get_counseling_playbook(区分, チャネル)` で配ることにした。チャットと音声が同じ状態と同じ playbook を読めること、切り替えを評価でツールの呼び出しとして機械判定できること(正規表現の許可リストの誤判定を繰り返さない)、切り替えの根拠が dip に残ること、が理由。

一方、会話の段階(相談・提案・支援・待つ)と「次に何を聞くか」はツールにしない。段階はターンごとに動くので、毎ターンの呼び出しを LLM が忘れて状態がずれる危険の方が大きく、結果は既存の `record_conversation_outcome` で足りる。次の質問をコードで決めると、v1 の相談モードが浅かった原因(項目を順に埋めるだけ)を固い形で残すことになる。深さは playbook の中身(明らかにすること・掘り下げ方)で作る。

旧リポジトリの ADR-0003(ツール呼び出し型の単一エージェント)は維持する。別のエージェントやグラフは作らない。

## Considered Options

- 相談を別のエージェント(またはグラフのノード)にする: 区分の切り替えのたびにエージェントを渡すことになり、会話の文脈とプロフィールの受け渡しが二重になる。ADR-0003 の判断と矛盾する
- 区分を Prompt の中だけで持つ(v1 の相談モードと同じ): 切り替えが見えず、評価・プロフィール画面・音声との共有ができない
- 次の質問を返すツール(`next_counseling_question`): 上記のとおり浅さを固定する
