# 設計メモ: ヒアリングでプロフィールが育つのを見せる(アルバイトと正社員)

日付: 2026-10-27。状態: 提案。対象: アルバイト・パートの相談(`dip_mcp/baito/`、PRD v4.1)と、正社員のヒアリング(`dip_mcp/career/`、[fulltime-hearing.md](fulltime-hearing.md))の、LINE のトークの見せ方。

## 1. 結論

- 答えるたびに、本人のプロフィールが埋まっていくのを見せる。部品は 3 つで、アルバイトと正社員で同じものを使う。
  - **帯**: 何かが埋まったターンに付ける小さな Flex。進み具合のバーと「6/10」、いま埋まった 1 行。
  - **プロフィールカード**: フェーズが変わるときに付ける Flex。埋まった項目と、まだの項目。
  - **完成**: 最後の Flex。アルバイトはプロフィールカードとおすすめの求人、正社員は職歴カードのカルーセルと下書き。
- 1 回の返信は、吹き出し 1 つと Flex 0〜1 つのまま。帯は小さいので、トークを埋めない。
- 得点、順位、ほめ言葉は出さない。「6/10」は進み具合で、評価ではない。
- 部品は `line_runtime/` に 1 つ作る。ハーネスは、ターンの結果に「進み具合」を足すだけにする。

## 2. なぜ

利用者の要望(2026-10-27、要旨): 質問の流れがテキストだらけではなく、UI も使って面白さを増やしたい。答えるたびに自分のプロフィールが完成していく過程が見えれば、苦痛はだいぶ減る。

今の作りでは、次の 2 つが見えない。

| | アルバイト | 正社員(fulltime-hearing.md §5.2) |
|---|---|---|
| UI | 無い。最初から最後まで、吹き出しとクイックリプライ | 職歴カードの Flex、まとめ、完成のカルーセル |
| 育つのが見えるもの | 何も無い | 職歴カードの 3 つの欄だけ。条件(なぜ今、勤務地、年収など)は、まとめまで見えない |

fulltime-hearing.md §5.1 の苦痛のうち、「終わりが見えない」「見返りが来ない」「何ができたか分からない」を、両方の相談で毎ターン減らす。

## 3. 部品

### 3.1 帯(毎ターン)

```
┌──────────────────────────┐
│ プロフィール ■■■■■■□□□□ 6/10          │
│ ＋ 働ける時間: 夕方以降                 │
└──────────────────────────┘
```

- **付けるとき**: そのターンに、数える項目(§4)が 1 つ以上埋まったとき。何も埋まらなかったターンには付けない。同じターンにプロフィールカードか完成を付けるときも、付けない。
- **中身**: 見出し「プロフィール」、バー、「埋まった数/全体」、いま埋まった項目の 1 行(「＋ 表示名: 値」)。2 つ以上埋まったら、1 行目だけを出し、「ほか 1 つ」を足す。
- **字数**: Flex の中の字は 24 字まで(数字とバーの記号を除く)。値は 10 字で切り、「…」を付ける。
- **形**: Flex の bubble。`size` は `micro` か `kilo`(LINE で見て決める)。バーは、色を付けた box と灰色の box の幅の比で描く。
- **altText**: 「プロフィール 6/10: 働ける時間を足しました」。

### 3.2 プロフィールカード(フェーズが変わるとき)

```
┌──────────────────────────┐
│ あなたのプロフィール            6/10   │
│ 条件  週3 / 夕方以降 / 駅から近い       │
│ 向き  人と話す? / テキパキ?            │
│ まだ  □ 時給  □ シフトの長さ           │
└──────────────────────────┘
```

- **付けるとき**: フェーズが変わる最初のターン(hard_filter の後、正社員は career_cards の後、review の前)。1 回の相談で 2〜3 回。
- **中身**: グループごとに 1 行。埋まった値は本人の言葉かボタンの文。場面の二択と逆選択から推し量った値には「?」を付ける(review で直せることを見せる)。まだの項目は灰色の「□ 表示名」。
- **字数**: Flex の中の字は 100 字まで。その代わり、そのターンの吹き出しは 40 字までにする。
- **グループ**:
  - アルバイト: 条件(HARD)、働き方(MID)、向き(場面の二択で推し量った値)、NG。
  - 正社員: 条件(HARD と MID)、職歴(職歴カードの数と、埋まった欄の数)。職歴カードの中身は、職歴カードの Flex が見せる。

### 3.3 完成(最後)

- **アルバイト**: プロフィールカード(全部)と、今の求人のカルーセル(`line_channel._cards_message`)。吹き出し 1 つ + Flex 2 つで、1 回の返信の上限 5 メッセージに収まる。
- **正社員**: fulltime-hearing.md §5.2 の「全部の完成」のまま(職歴カードのカルーセル、下書きを開くボタン、空欄の数)。先頭に、条件のプロフィールカードを 1 枚足す。

### 3.4 どれを付けるか(1 ターンに Flex は 0〜1 つ)

優先の順: 完成 > プロフィールカード > 職歴カード(正社員。欄が埋まったターン) > 帯。

正社員の職歴カードは、それ自体が進み具合を見せるので、職歴カードを付けるターンには帯を付けない。帯の数には、職歴カードの欄も入れる。

## 4. 何を数えるか

| | 全体(分母) | 埋まった(分子) |
|---|---|---|
| アルバイト | 本人の区分の表の HARD と MID(`SLOT_PRIORITY`)。LOW は入れない | 値が入った項目。「こだわりなし」、パス、review で「未定」にした項目も入れる |
| 正社員 | 条件の HARD と MID(§3.2 の表) + 職歴カードの欄(1 枚 3 つ × 枚数) | 同上。職歴カードの欄の「パス」「覚えていない」も入れる |

- **分母が決まるまでは出さない**。アルバイトは区分、正社員は segment が決まってから、帯を出し始める。区分が変わったら、新しい表で数え直す。
- **分子は減らさない**。review で値を直しても、消しても(「未定」)、埋まったままに数える。答えたことは減らないため。
- 時間の予算で聞かなかった項目は、最後まで「□」のまま出る。全部埋まらなくても、完成のカードは出す。

## 5. ハーネスとランタイムの受け持ち

- **ハーネス**(`dip_mcp/baito/`、`dip_mcp/career/`): ターンの結果に `progress` を足す。中身は表示に要るものだけ。
  - `filled`、`total`、`added`(このターンに埋まった項目の表示名と値)、`groups`(グループの名前と、項目の表示名・値・推し量ったか)、`milestone`(フェーズが変わる最初のターンか)、`complete`(最後か)。
  - 何を数えるかは §4 のとおりで、ハーネスが決める。ランタイムは数えない。
- **ランタイム**(`line_runtime/`): `progress` から、§3.4 の順で Flex を 0〜1 つ選び、返信に足す。Flex を作る関数は 1 つのモジュールにまとめ、アルバイトと正社員で使う。
- **形 C(Flex なし)と Web のトーク**(`talk-core.js`): 帯は、吹き出しの最後の 1 行「(6/10 ＋働ける時間)」に落とす。プロフィールカードは、短い文に落とす。
- Flex の中の字を文にする関数を用意する。評価の本人役(fulltime-hearing.md §6.1)が読めるようにするため。

## 6. 評価

- **正社員**: 帯とプロフィールカードは形 D に入る(fulltime-hearing.md §6.5)。推定時間には、Flex の中の字も読む字として数える(§3.3)。帯 24 字は約 3.6 秒で、12 ターンなら約 43 秒になる(推定時間の式からの計算)。帯で速く進むか、読む時間で遅くなるかは、5/5 のタスクが測る。D が C より遅いときは、帯を切った形でも測る(帯の出し入れは設定 1 つ)。
- **アルバイト**: 推定時間の評価がまだ無い。この UI のタスクでは、LINE の上限、どのターンに何を付けるか、画面の写真を確かめる。本人役での計測は、後のタスクにする。
- 実機の LINE での見え方(`micro` で字が読めるか、バーの色)は、写真と実機で確かめる。

## 7. 決めたこと、決めていないこと

決めたこと(2026-10-27、利用者):

1. 毎ターンの小さな帯と、区切りの大きなプロフィールカードを使う。
2. アルバイトと正社員で同じ部品を使う。先にアルバイトで作り、正社員の UI(3/5)が使う。
3. 得点、順位、ほめ言葉は出さない。

決めていないこと:

- 帯の `size`(`micro` か `kilo`)とバーの色。実機の LINE で見て決める。
- アルバイトの PRD v4.1 には UI の決まりが無い。このメモが、アルバイトの UI の正になる。PRD を直すかは利用者が決める。
