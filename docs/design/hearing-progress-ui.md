# 設計メモ: ヒアリングでプロフィールが育つのを見せる(アルバイトと正社員)

日付: 2026-10-27。状態: 提案。

アルバイトの相談の始まり方(入口から求人まで)は、[baito-quick-start.md](baito-quick-start.md) で置き換えた。このメモの帯とプロフィールカードは、アルバイトでは「もっと絞る」の間だけ使う。

対象は、LINE のトークでの 2 つの相談の見せ方。

- アルバイト・パートの相談(`dip_mcp/baito/`、PRD v4.1)
- 正社員のヒアリング(`dip_mcp/career/`、[fulltime-hearing.md](fulltime-hearing.md))

## 1. 結論

- 答えるたびに、本人のプロフィールが埋まっていくのを見せる。部品は 3 つで、アルバイトと正社員で同じものを使う。
  - **帯**: 何かが埋まったターンに付ける小さな Flex。進み具合のバーと「6/10」、いま埋まった 1 行。
  - **プロフィールカード**: hard_filter が終わったときに付ける Flex。埋まった項目と、まだの項目。
  - **完成**: 最後の Flex。アルバイトはプロフィールとおすすめの仕事、正社員は今の設計の完成に条件のカードを足す。
- 1 回の返信は、どの場面でも吹き出し 1 つと Flex 0〜1 つ。帯は小さいので、トークを埋めない。
- 得点、順位、ほめ言葉は出さない。「6/10」は進み具合で、評価ではない。
- 部品は `line_runtime/` に 1 つ作る。ハーネスは、ターンの結果に「進み具合」を足すだけにする。

## 2. なぜ

利用者の要望(2026-10-27、要旨): 質問の流れがテキストだらけではなく、UI も使って面白さを増やしたい。答えるたびに自分のプロフィールが完成していく過程が見えれば、苦痛はだいぶ減る。

今の作りでは、次の 2 つが見えない。

| | アルバイト | 正社員(fulltime-hearing.md §5.2) |
|---|---|---|
| UI | 無い。最初から最後まで、吹き出しとクイックリプライ | 職歴カードの Flex、まとめ、完成のカルーセル |
| 育つのが見えるもの | 何も無い | 職歴カードの 3 つの欄だけ。条件(なぜ今、勤務地、年収など)は、まとめまで見えない |

fulltime-hearing.md §5.1 の苦痛のうち、「終わりが見えない」「見返りが来ない」「何ができたか分からない」を、両方の相談で毎ターン減らす。

## 3. 部品

### 3.1 帯

```
┌──────────────────────────┐
│ プロフィール ■■■■■■□□□□ 6/10          │
│ ＋ 働ける時間: 夕方以降                 │
└──────────────────────────┘
```

- **付けるとき**: そのターンに、数える項目(§4)が 1 つ以上埋まったとき。何も埋まらなかったターンには付けない。§3.4 で上の部品を付けるターンにも、付けない。
- **中身**: 見出し「プロフィール」、バー、「埋まった数/全体」、いま埋まった 1 行(「＋ 表示名: 値」)。
- **2 つ以上埋まったとき**: 表のいちばん上の 1 つを出し、後ろに「ほか N」を足す(N は残りの数)。区分が決まって、保留した答えがまとめて入るターンなどで起きる。
- **字数**: 見出し、バー、数字を除いた字(「＋ 表示名: 値」と「ほか N」)を 24 字までにする。「＋ 表示名: 値」が 20 字を超えるときは、値を切って「…」を付ける。
- **形**: Flex の bubble。`size` は `micro` か `kilo`(実機の LINE で見て決める)。バーは、色を付けた box と灰色の box の幅の比で描く。
- **altText**: 「プロフィール 6/10: 働ける時間を足しました」。

### 3.2 プロフィールカード

```
┌──────────────────────────┐
│ あなたのプロフィール            6/10   │
│ 条件    週3 / 夕方以降 / 駅から近い     │
│ 働き方  人と話す? / 時給1100円          │
│ NG     深夜                            │
│ まだ    □ シフトの長さ  □ 体を使う      │
└──────────────────────────┘
```

- **付けるとき**: hard_filter から次のフェーズに移った最初のターン。1 回の相談で 1 回。正社員は、career_cards から次に移った最初のターンにも付ける(計 2 回)。
- **review の前には付けない**。review の吹き出し(アルバイト)と、まとめの Flex(正社員)が、同じ役を持つため。
- **グループ**: 「条件」は HARD、「働き方」は MID、「NG」は NG の一覧。LOW は出さない。
- **値**: 本人の言葉かボタンの文。場面の二択と逆選択から推し量った値には「?」を付ける(review で直せることを見せる)。review で「未定」にした項目は「未定」と書く。
- **まだ**: まだ答えていない項目は、灰色の「□ 表示名」。
- **字数**: Flex の中の字は 80 字まで。収まらないときは、「まだ」の項目を減らし、「ほか N」とする。
- 正社員の職歴カードの中身は、職歴カードの Flex が見せる。プロフィールカードには「職歴 2 枚、欄 4/6」の 1 行だけを出す。

### 3.3 完成

- **アルバイト**: 1 つの bubble に、プロフィール(§3.2 と同じグループ)とおすすめの仕事の 3 行を並べる。
  - おすすめの仕事は、結果の `recommendations` の職種(`catalog_v4.json` の `name`)と理由。求人のカード(`line_channel._cards_message`)ではない。今の結果は、求人ではなく職種を返すため。
  - 結果の吹き出し(`compose_result_text`)は、今のまま出す。注意の文と「未定」の行を、Flex だけに頼らないため。
- **正社員**: fulltime-hearing.md §5.2 の「全部の完成」のカルーセルの、先頭の bubble に条件のプロフィールカードを入れる。カルーセルは 1 つの Flex なので、Flex 0〜1 つの決まりの中に収まる。

### 3.4 どれを付けるか

1 ターンに Flex は 0〜1 つ。いくつも当てはまるときは、上のものを付ける。

1. 完成
2. まとめ(正社員の review)
3. プロフィールカード
4. 職歴カード(正社員。欄が埋まったターン)
5. 帯

review のターンには、帯を付けない。正社員の職歴カードは、それ自体が進み具合を見せるので、職歴カードを付けるターンには帯を付けない。帯の数には、職歴カードの欄も入れる。

## 4. 何を数えるか

アルバイトの「区分」と、正社員の「segment」を、ここではまとめて区分と呼ぶ。

| | 全体(分母) | 埋まった(分子) |
|---|---|---|
| アルバイト | 今の区分の表の HARD と MID(`SLOT_PRIORITY`)。LOW と NG は入れない | 分母の項目のうち、値が入ったもの。「こだわりなし」、パス、review で「未定」にした項目も入れる |
| 正社員 | 今の区分の条件の HARD と MID(fulltime-hearing.md §3.2) + 職歴カードの欄(1 枚 3 つ × 枚数) | 同上。職歴カードの欄の「パス」「覚えていない」も入れる |

- **出し始め**: hard_filter の最初のターンから。icebreak の間は出さない。
- **区分が決まらない人**: 区分が `unknown` のまま進んだ人は、`unknown` の表(アルバイトは `COMMON`)で数える。
- **区分が変わったとき**: 新しい表で、分母と分子を数え直す。新しい表に無い項目(`_switch_segment` が archived に移すもの)は数えない。このときだけ、分子が減ることがある。分子が分母を超えることはない。
- **ほかのとき、分子は減らさない**。review で値を直しても、「未定」にしても、埋まったままに数える。
- 時間の予算で聞かなかった項目は、最後まで「□」のまま出る。全部埋まらなくても、完成は出す。

## 5. ハーネスとランタイムの受け持ち

- **ハーネス**(`dip_mcp/baito/`、`dip_mcp/career/`): ターンの結果に `progress` を足す。中身は、表示に要るものだけ。
  - `filled`、`total`: §4 の数
  - `added`: このターンに埋まった項目の表示名と値
  - `groups`: グループの名前と、項目の表示名・値・推し量ったか・未定か
  - `milestone`: §3.2 のプロフィールカードを付けるターンか
  - `complete`: 最後のターンか。アルバイトは、おすすめの仕事の職種名と理由も入れる
  - 何を数えるか、どのターンが `milestone` かは、ハーネスが決める。ランタイムは数えない。
- **ランタイム**(`line_runtime/`): `progress` から、§3.4 の順で Flex を 0〜1 つ選び、返信に足す。Flex を作る関数は 1 つのモジュールにまとめ、アルバイトと正社員で使う。
- **Flex を切った形と Web のトーク**(`talk-core.js`): 帯は、吹き出しの最後の 1 行「(6/10 ＋働ける時間)」に落とす。プロフィールカードと完成は、短い文に落とす。
- Flex の中の字を文にする関数を用意する。評価の本人役(fulltime-hearing.md §6.1)が読めるようにするため。

## 6. 評価

- **正社員**: 帯とプロフィールカードは形 D に入る(fulltime-hearing.md §6.5)。推定時間には、Flex の中の字も読む字として数える(§3.3)。
  - 帯 24 字は約 3.6 秒で、12 ターンなら約 43 秒になる。プロフィールカード 80 字 × 2 回は約 24 秒。どちらも推定時間の式からの計算。
  - 履歴書ありの人は、質問を止める時刻が 90 秒なので、聞ける数が減りうる。
  - 帯で速く進むか、読む時間で遅くなるかは、5/5 のタスクが測る。D が C より遅いときは、帯を切った形でも測る(帯の出し入れは設定 1 つ)。
- **アルバイト**: 推定時間の評価がまだ無い。この UI のタスクでは、LINE の上限、どのターンに何を付けるか、画面の写真を確かめる。本人役での計測は、後のタスクにする。
- 実機の LINE での見え方(`micro` で字が読めるか、バーの色)は、写真と実機で確かめる。

## 7. 決めたこと、決めていないこと

決めたこと(2026-10-27、利用者):

1. 毎ターンの小さな帯と、区切りの大きなプロフィールカードを使う。
2. アルバイトと正社員で同じ部品を使う。先にアルバイトで作り、正社員の UI(3/5)が使う。
3. 得点、順位、ほめ言葉は出さない。

決めていないこと:

- アルバイトの PRD v4.1 には、UI の決まりが無い。このメモを、アルバイトの UI の正とする。PRD を直すかは、利用者が決める。
